# 防丢档与额度耗尽应急协议（A/B/C 全员强制）
> 适用于 Hark AI A（故事）、B（美术）、C（工程），也适用于之后接手本仓库的其他 AI。**重要：这是一项持续执行规范，不是等快没额度才执行一次的任务。**

## 0. 核心原则
所有对项目有价值的成果都应该**尽快离开单台临时电脑/会话**，进入用户拥有的 GitHub 仓库 `Yichenyu19/ai-ziling`。聊天里的“已完成”宣称、远程临时路径、未上传的本地文件不算完成交付。

- 不需要等作品完整：草稿、可复用素材、已经验证可运行的脚本、失败经验也值得保留。
- 任何 GitHub 提交必须在各自工作目录/功能分支进行，不直接推 `main`，不覆盖别人文件。
- 只有公开安全、版权/来源清晰的东西才能推到公开仓库。不得泄露 Token、API key、cookie、个人登录信息、未经允许的私有仓库资产。
- **本地制作与远端上传要分开确认**：能访问公开仓库不等于能推送，必须确认远端 commit URL/PR URL 和文件可见，不能凭 `git commit` 就说“已备份”。

## 1. 额度策略
每个 AI 在可查询时记录本账号**本日总额度、当前剩余额度、记录时间及来源**，不要拿整个账户的额度池 `pool_left` 代替当日 `daily_left`；不清楚计量单位时不得声称是 token。

- **平时**：每完成一个可复用里程碑，立刻提交/打包一次；在连续工作期间至少每完成一个主要成果保存一次；长时间工作不可一直囤本地未提交文件。
- **剩余 <=25%**：进入防丢档预警，暂停扩展范围、优先把已有成果提交/打包，开始写交接。
- **剩余 <=10%**：**紧急冻结创作**。不再开新任务、不再长时间渲染。优先将全部最新源文件、可编辑美术、分镜、时间轴、制作资产、阶段性可播放视频、评估和经验上传；执行必要的验证后发远端提交/PR/附件索引。即使作品没做完也要留下可以接着做的半成品与上下文。
- **额度查询失败、被标记 unknown、无法得知剩余量或可能突然归零**：直接按更保守的节奏保存，不得依靠触发10%的检查作为唯一保护。

如果按已见到的每日 8,000,000 **额度单位**做粗略基准，25% 为 2,000,000，10% 为 800,000；具体以各账号真实当日上限为准。不能用上次快照推断实时数值。**保存也要消耗时间和额度**，不能等只剩最后几步时才开始打包。

## 2. 每次检查点应该保存什么
所有成果按负责人独立区域存储：
- A：`films/ai-jiahao/pilot20/story/`
- B：`films/ai-jiahao/pilot20/art/`
- C：`films/ai-jiahao/pilot20/animatic/`

在各自目录内维护一个 **`CHECKPOINT.md`**，至少写清：
1. 本次工作基于哪个公开仓库 commit、需求版本、实际已完成什么。
2. 每个成果的**相对路径、文件名、格式、打开/构建命令、可见验证方式**。
3. 最新决定、关键假设与为什么这样设计；失败的尝试及原因。
4. 哪些经过测试、哪些是未验证主张。
5. 当前断点；下一位 AI 从哪条具体命令和哪个文件开始。
6. 已提交远端的 **commit URL / PR URL**，未提交文件清单，附件清单与完整校验值（如可取得 SHA-256）。
7. 如存储成本/权限限制阻碍上传，说明具体缺什么以及如何恢复。
绝不能只保存“今日工作总结”，却把关键 SVG/PSD/PNG/脚本/时间轴/音频/草稿留在本地。

## 3. 上传与验证
**优先：** 各自合法 GitHub 写权限 → 独立分支 → commit & push → PR/commit URL → 在未授权会话中测试仓库能否读取。重要中间节点即使未完成也可以提交，使用 `WIP` 标记。

**无写入权限时：** 立即打包完整工作目录（包括真实源文件，不只报告），作为 Hark 真实附件交付，附 SHA-256 和文件清单；将关键文字工作和目录结构直接放进聊天回复；把**待入库**状态明确标出来，通知总导演代为入库。附件传输成功、能被总导演下载和上传 GitHub 后才算真正完成防丢档。不能把“生成了附件”冒充“GitHub 已备份”。

**公开仓库大文件处理：** 避免将大量视频帧、超大临时缓存或运行时下载依赖直接塞进 Git 历史。必要时保存原始可重建源码 + 代表性样片/关键资产，将大文件留待总导演批准使用 GitHub Releases 或外部归档。不可擅自删掉唯一副本。

## 4. 额度触发后的最小应急回复
```
[CHECKPOINT / 任务 A|B|C]
本次剩余额度（来源、查询时间、日额度上限）：
目前状态：进行中 / 已完成 / 未验证
已保存 GitHub：commit / PR URL、具体路径
未成功保存的文件：逐项列举
附件：文件名、大小、校验值、交付是否成功
下一步：下一个 AI 只需做哪一件事
风险与阻塞：
```
若剩余 <=10%，请发出此报告后**停止继续消耗额度做非必要创作**。总导演审核备份完整性，再决定是否继续/换号。

## 5. 注意平台限制
外部调度系统的余额数据可能是延迟缓存；自动检测也可能失灵或错过阈值。**“始终边做边存”比“等 10% 告警才存”更加可靠。**
